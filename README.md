# DefenceLens

Работающий MVP для небольшого волонтёрского центра: логи → детекторы → инциденты → доказательства → влияние → рекомендации → проверка результата.

## Запуск

Нужны Docker Engine и Docker Compose. На хосте не нужны Node.js, Python или Trivy.

```bash
cp .env.example .env
docker compose up -d --build
```

- Интерфейс: http://localhost:18080
- API / OpenAPI: http://localhost:18000/docs
- Токен локального демонстрационного запуска: `local-development-token`. Можно заменить API_TOKEN в .env.
- Первое сканирование загружает базу Trivy через интернет; интерфейс показывает ожидание, ошибку и повтор.

Порты привязаны к localhost. Перед доступом через внешнюю сеть настройте TLS, отдельные секреты и ограничения доступа. MVP использует один операторский bearer-токен, а не многопользовательскую модель доступа.

## Демонстрация за 5 минут

1. Войдите с API_TOKEN. Нажмите «Загрузить демо». Это явное создание **синтетических** данных; при старте пустая БД не заполняется.
2. На обзоре появятся четыре детектора, график и индекс внимания. Откройте объяснение расчёта.
3. Откройте инцидент ошибок API. Прочитайте факты, ограничения, временную шкалу и влияние на gateway. Недоступность API мешает отправке заявок.
4. В карточке сохраните действие «В работе» и пояснение. «Проверить результат» анализирует события после действия (максимум 5 минут); без новых HTTP-ответов выводится «недостаточно данных».
5. В «Источниках» загрузите JSONL или Nginx common/combined access.log. Счётчики принятых, повторных и отклонённых строк отображаются отдельно.
6. Для потокового сценария допишите JSONL в `demo/logs/live.jsonl`. После загрузки демо Vector уже настроен на `vector-demo`; обновления появляются без перезагрузки.
7. `docker save redis:7.4.2-alpine -o /tmp/redis.tar`; загрузите архив на странице «Образы». Не нужно запускать этот образ. Trivy показывает реальные CVE, компоненты и потенциальные секреты (значения секретов не сохраняются).
8. Укажите сервис и период deployment. Подтверждение оператором требует основания: digest из CI/deployment или ссылки на запись развёртывания. Это утверждение оператора, не автоматическая проверка runtime.

Для своего Vector создайте сервис и источник, укажите VECTOR_SOURCE_ID в .env и выполните `docker compose up -d vector`. Пример конфигурации в `vector/vector.yaml`. Директорию сбора можно заменить в volume Compose.

## Формат логов

JSONL, массив JSON или один объект для HTTP. Timestamp обязателен и должен включать часовой пояс.

```json
{"event_id":"stable-id-123","timestamp":"2026-10-03T16:00:00Z","event":"login_failed","user":"coordinator","ip":"203.0.113.24"}
{"event_id":"stable-id-124","timestamp":"2026-10-03T16:00:01Z","status":503,"method":"POST","path":"/requests"}
```

Timestamp в примере замените текущим временем. Типы аутентификации: login_failed, login_success. HTTP 401 сам по себе не классифицируется как отказ аутентификации. Для демонстрационных данных добавьте `"synthetic":true`.

```bash
curl -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/x-ndjson" \
  --data-binary @events.jsonl \
  http://localhost:18000/api/ingest/SOURCE_ID
```

Идемпотентность: уникальные `(source_id, SHA256(event_id))`; без event_id хешируется нормализованное событие. Сохраните event_id при повторе. Одинаковые события без ID могут схлопнуться. Доставка между разными источниками автоматически не дедуплицируется.

HTTP подтверждение отправляется после транзакции PostgreSQL. Повторные параллельные пакеты сериализуются блокировкой сервиса. Некорректные строки возвращаются в `errors`, счётчик rejected сохраняется. Валидные строки в смешанном пакете принимаются; Vector не исправляет невалидные строки автоматически. Отклонённые исходные данные остаются в исходном файле, подробный dead-letter storage в MVP отсутствует. Лимит пакета: 2000 событий / 5 MiB.

## Детекторы

- 5 отказов одного IP/пользователя за 5 минут.
- Успешный вход той же пары после ≥5 отказов за 5 минут.
- HTTP-сигнатуры traversal, .env/.git, SQL union select, script, wp-admin.
- ≥10 HTTP-событий за 5 минут, ≥5 ответов 5xx, доля ≥30%, рост ≥20 процентных пунктов относительно предшествующих 5 минут. Без baseline фиксируется высокий уровень, а рост явно не подтверждается.

Анализ синхронно выполняется при приёме, без LLM и Redis. Запоздавшие события переоценивают окружение ±10 минут. Близкие срабатывания объединяются в 15-минутный эпизод; сохраняется до 200 ссылок на доказательства. Повторные факты могут переоткрыть решённый эпизод.

Сигнатуры дают гипотезы, не подтверждение взлома. Отсутствие логов не равно отсутствию угроз. Не выполняются действия на серверах.

## Архитектура и устойчивость

- FastAPI / Pydantic / SQLAlchemy / Alembic, PostgreSQL 16.
- React / TypeScript / Vite, TanStack Query polling 5s, Recharts, Tailwind и единые компоненты.
- RQ worker запускает только бинарник Trivy с фиксированными аргументами; пользовательский образ не исполняется, Docker socket не монтируется.
- PostgreSQL хранит durable pending-записи сканирования. Dispatcher каждые 5 секунд сверяет их с RQ; после восстановления Redis задачи ставятся в очередь.
- Trivy получает две автоматические повторные попытки; окончательная ошибка допускает ручной повтор. Redis AOF и PostgreSQL используют постоянные volumes.
- Vector: дисковый буфер, acknowledgements, retry HTTP доставки и checkpoint файлов.
- Архивы: потоковая загрузка до 512 MiB, проверка manifest и внешних путей/ссылок без распаковки. Worker: non-root, no-new-privileges, без capabilities, 2 CPU / 2 GiB.
- Результаты Trivy не сохраняют Match/Code секретов. Для ссылок CVE интерфейс допускает только HTTPS.
- Индекс: P1=25, P2=12, P3=5 × importance/5; до 15 за текущий подтверждённый образ (Critical×5 + High×2); сумма ограничена 100. Не является вероятностью взлома.

## Проверки

```bash
# Изолированные тесты API и правил (SQLite только в тестах)
docker compose run --rm --no-deps -v "$PWD/backend:/app" api python -m pytest -q -p no:cacheprovider

# Реальная БД, конкурентная доставка, Vector; добавляет помеченные synthetic события
python3 scripts/integration.py

# Браузер: установленный Playwright + Chrome
node scripts/browser-smoke.cjs
```

Для browser smoke модуль playwright должен быть доступен Node (например через NODE_PATH). BASE_URL, WEB_URL, API_TOKEN настраиваются переменными среды. Скриншоты сохраняются в test-results.

```bash
docker compose ps
docker compose logs --tail 100 api worker dispatcher vector
docker compose stop
# Повторный запуск сохраняет данные
docker compose up -d
```

## Границы MVP

Один доверенный оператор; нет RBAC и неизменяемого внешнего аудита. История хранит действия в БД. Нет автоматического discovery deployment, эксплойт-верификации и гарантии покрытия всех атак. Нет автоматического удаления старых логов/образов: контролируйте диск. Анализ окон выполняется в памяти и рассчитан на небольшой поток, не заменяет SIEM для больших объёмов. Для production нужны нагрузочные испытания, retention, резервное копирование и усиление аутентификации.

Подтверждённое развёртывание — заявление оператора с основанием. Похожесть событий по времени не доказывает причинность. CVE не доказывает эксплуатацию. Сканирование образа не заменяет runtime-логи.

Документация интеграций: [Trivy image](https://trivy.dev/docs/dev/references/configuration/cli/trivy_image/), [Vector HTTP sink](https://vector.dev/docs/reference/configuration/sinks/http/), [RQ retries](https://python-rq.org/docs/), [Vite](https://vite.dev/guide/).
